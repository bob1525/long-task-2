# 任务 B：分布式键值存储模拟器

这个目录是一个独立的离散事件模拟器，用来比较两种可切换的一致性模型，并在测试里自动检查操作历史。它不修改、也不依赖仓库里的 Fun 编译器。实现只使用 Python 3 标准库。

## 架构

时间是整数毫秒。`Simulator` 用一个堆维护事件；处理函数可以注册后续事件，但不能再进入 `run_for` / `run_until`。每个节点还有 Lamport 时钟。最终一致模型另用混合逻辑时钟（HLC）给版本盖戳，物理时间是 `模拟时间 + 该节点的时钟偏移`。

| 模块 | 职责 |
| --- | --- |
| `kvsim/sim.py` | 事件队列、HLC |
| `kvsim/network.py` | 延迟、按概率丢包、分区、测试用过滤器 |
| `kvsim/cluster.py` | 节点配置、客户端、崩溃/恢复、调用检查器 |
| `kvsim/eventual.py` | 最终一致的 LWW 寄存器 |
| `kvsim/raft.py` | Raft 复制和 read-index 读 |
| `kvsim/checker.py` | 线性化、收敛、Raft 安全 |
| `kvsim/demo.py` | 可被测试调用的分区演示 |
| `kvsim/faults.py` | 24 个固定种子的故障场景和汇总报告 |

网络只切断**节点之间**的消息。测试客户端可以直接调用任一存活节点，这样分区之后仍然能观察每一侧；这和 Jepsen 里“客户端不在被分区的节点网络里”是同一种摆法。分区在发送和投递时都会再检查，所以已经在路上的消息如果端点已经不连通，会被丢掉。未列入任何分组的节点各自孤立。

崩溃会停掉选举、反熵和未完成的读，但**保留**已接受的日志、状态机、任期、`votedFor` 和存储。恢复后节点以跟随者身份重新加入，数据还在。

`python3 -m kvsim demo` 和 `python3 -m kvsim faults` 是命令行入口。设置环境变量 `KVSIM_TRACE=1` 会打印带模拟时间的事件。

## 一致性模型

配置项 `ClusterConfig.model` 取 `eventual` 或 `linearizable`。两边的客户端 API 一样：`put` / `get`，并可指定 `contact`（只联系这一个节点）或 `prefer`（先试这个节点，失败再换）。

### 最终一致性

单副本写入（W=1）。每个成功的写用写入者当时的 HLC 盖戳，版本序是 `(wall, logical, writer_id)`，三者都更大者胜出。同一个版本不会被更旧的版本替换。

传播有三条路径，合并规则相同：

- 立即复制：写入后推给其他副本（可关）。
- 反熵：周期性地推拉整份存储。`ae_fanout=0` 表示推给所有对等节点，大于 0 则随机抽这么多个。
- 读修复：读会询问若干副本。返回前重新读取本地存储，把等待期间安装进来的版本算进去，取最大版本写回本地，并推给回答了更旧版本的副本。

分区期间两侧都能写，读可以返回旧值，所以它**不是**线性一致。愈合并且不再有新写入之后，存活副本应收敛到每个键的最大 HLC 版本。时钟偏移可以让更早发生的写入盖上更大的 `wall`，从而在愈合后赢过后来的写入；这是 LWW 的语义，不是墙上时钟顺序。

### 线性一致性

三个或更多节点跑 Raft（单节点则自己成为领导者）：

- 任期、投票和日志跨崩溃保留。
- 投票要求候选人的日志至少和自己一样新。
- 领导者只把提交点推进到**当前任期**的日志项上（Figure 8）；这个提交会连带提交它前面的前缀。
- 同一次客户端调用的重试沿用同一个 `req_id`，领导者不会把这一次请求追加两次。每个 `client()` 句柄有自己的会话号：两个句柄即使显示名相同，也是两次不同的写入。
- 读只由领导者服务。领导者必须已经提交过本任期的一条日志，并且在这次读开始之后得到多数派的心跳确认，然后才返回已经应用到状态机里的值。第一轮带读标记的心跳如果丢了，后面的心跳和日志重试仍带着这个标记，读不会停在已经追上的集群上。

少数派不能提交。旧领导者在分区一侧收不到多数派心跳时，不能把新写入提交，也不能完成一次线性读。`unsafe_stale_reads` 不是第三种模型：它让任意副本直接用本地状态回答读，只用来证明检查器抓得住过期读。

## 一致性检查器

客户端每次调用都会记入历史：开始时间、结束时间、状态（`ok` / `timeout` / `unavailable`）。`Cluster.verify()` 在测试末尾自动跑。

线性化按键拆开（Herlihy 与 Wing 的局部性）。每个键是一个寄存器，搜索是 Wing/Gong 的回溯，并用 `(当前值, 已线性化操作的位集)` 做备忘。真实时间上，只有成功操作的结束时间**严格小于**另一个操作的开始时间，才强制排在前面；同一会话里更早的成功调用也保持程序顺序。相等的时间戳视为并发。

超时的写入是不确定的：它可能根本没发生，也可能在客户端放弃之后才落上。检查器按 Jepsen/Knossos 的方式枚举这些写入的子集；超时写入本身没有响应，所以它不排在别的操作前面。`unavailable` 表示请求没有被接受，不参与解释任何值。搜索超出上限时结果是 `INCONCLUSIVE`，测试不会把它当成通过。

最终一致检查三件事。存活副本的存储必须一致；每个版本都确实是某个副本创建过的；同一 `(wall, logical, writer)` 不能对应两个值。`durable=True`（所有写过数据的副本都已恢复、并且已经留出反熵时间）还要求每个存活副本持有该键的最大 HLC 版本。副本还活着但最大版本只在一台已崩溃的机器上时，用 `durable=False` 只检查目前存活副本是否已经达成一致。

Raft 安全检查另外确认：已提交前缀在所有节点上相同，状态机等于日志重放，`lastApplied == commitIndex`，同一任期没有两个存活领导者，以及节点自己记录的“拒绝截断已提交日志”“提交点回退”等违规。

## 运行测试

在 `task-b-distributed-kv/` 下：

```bash
python3 -m unittest discover -s tests -v
```

必须用 `discover -s tests`。这样 `tests/` 会在导入路径上，`import support` 才能成功。

只跑一类：

```bash
python3 -m unittest discover -s tests -k test_raft -v
python3 -m unittest discover -s tests -k test_eventual -v
python3 -m unittest discover -s tests -k DeliberateViolation -v
```

分区演示（两种模型都会跑，并在结尾调用检查器）：

```bash
python3 -m kvsim demo
python3 -m kvsim demo --model eventual --seed 1
python3 -m kvsim demo --model linearizable --seed 1
```

最终一致的演示把 4 个节点切成 `{0,1} | {2,3}`，两侧分别写 `red` 和 `green`，分区期间收敛检查失败；愈合后反熵收敛，并且检查通过。线性一致的演示把领导者单独隔开，少数派写入超时，多数派写入成功，愈合后读到的仍是多数派的值。

24 个故障场景（偶数种子走线性一致，奇数种子走最终一致；种子能被 4 整除时用 5 个节点）会注入分区、丢包和崩溃，每个场景结束前先愈合、恢复全部节点，再跑检查器：

```bash
python3 -m kvsim faults
python3 -m kvsim faults --seed 2
```

报告列是 `seed / model / nodes / drop / ops / PASS|FAIL`，最后一行是 `total/passed/failed`。任一场景失败时进程退出码为 1。
