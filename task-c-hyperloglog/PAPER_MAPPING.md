## 秩和分桶

Figure 3 给出三个例子：`ρ(1···) = 1`，`ρ(0001···) = 4`，`ρ(0^K) = K + 1`。`rho` 对宽度为 `width` 的字计算前导零个数加 1；全 0 时返回 `width + 1`。这读的是写在左边的高位，不是整数最低位的那个 1。

分桶是：

```text
j = 1 + <x1 x2 … xb>_2
w = x_{b+1} x_{b+2} …
M[j] = max(M[j], ρ(w))
```

`x1` 是 32 位字的最高位。代码里的下标是 `j − 1`，也就是前 `b` 位的整数值，存在 `registers[0 .. m−1]`，对应论文的 `M[1] .. M[m]`。`split_hash` 用 `word >> (32 − b)` 取这个下标，剩下的低 `32 − b` 位才送去算 `ρ`。

`b = 4`、字为 `0x11000000` 时，前 4 位是 `0001`，下标为 1，余下字段以 `0001` 开头，`ρ = 4`。`tests/test_rho.py` 锁住这个例子。若误用最低 4 位做下标，这个测试不会过。

## 原始估计和 α_m

空寄存器按 Figure 3 的初值 0 参加求和，`2^{−0} = 1`。因此空集的原始估计是

```text
E = α_m m² / m = α_m m
```

`m = 16` 时是 `0.673 × 16 = 10.768`。Section 4 (ii) 正是用这个例子说明必须做小范围修正：不修正的话 `n = 0` 会得到大约 `0.7m`。

Figure 3 印出的常数：

```text
α_16 = 0.673
α_32 = 0.697
α_64 = 0.709
α_m = 0.7213 / (1 + 1.079/m)    当 m ≥ 128
```

`alpha_m` 原样使用这些数。`m = 64` 不套用大 `m` 公式：那个公式在 `m = 64` 处约为 `0.70934`，和印出的 `0.709` 差在小数第四位。

Equation (3) 的积分是

```text
α_m = ( m ∫_0^∞ (log2((2+u)/(1+u)))^m du )^{−1}
```

`moment_integral` 用分段 Simpson 计算 `J_0(m)`。求积结果约为 `α_16 = 0.673102`，`α_32 = 0.697123`，`α_64 = 0.709208`，四舍五入到三位小数就是 Figure 3 的三个常数。`m ≥ 128` 的闭合式来自 (28)–(29) 的 Laplace 近似：`1/(2 ln 2) ≈ 0.721347`，程序写成 `0.7213`；`3 ln 2 − 1 ≈ 1.07944`，程序写成 `1.079`。测试要求这个闭合式与积分相差不超过 `10^{−4}`。

## 三段修正

Figure 3 的算术部分是：先算原始 `E`，再按范围得到 `E*`。`apply_corrections` 的三个分支对应图里的三处花括号。

小范围，Section 4 (ii)。`n` 个球随机丢进 `m` 个桶，空桶数大约是 `m e^{−μ}`，`μ = n/m`。看到 `V` 个空桶（寄存器仍为 0）时，

```text
n ≈ m ln(m/V)
```

程序写成 `E* := m log(m/V)`，条件是 `E ≤ (5/2) m` 且 `V ≠ 0`。`V = 0` 时保留原始 `E`。比较用的是原始 `E`，不是修正后的值：`V = 1` 时线性计数等于 `m ln m`，可以大于 `(5/2)m`，但分支已经由原始 `E` 决定。

端点用 `≤`，因为 Figure 3 写的是 `E ≤ (5/2) m`。正文说失真出现在基数小于 `(5/2)m`、渐近区间在这个值上已经达到；真正被执行的是程序图，所以相等时仍走线性计数。

中间范围：`(5/2)m < E ≤ 2^{32}/30` 时 `E* = E`。大范围的不等式是严格的 `>`，所以 `E = 2^{32}/30` 不做碰撞修正。

大范围，Section 4 (iii)。32 位哈希下，不同哈希值的个数大约是 `2^{32}(1 − e^{−n/2^{32}})`。原始估计 `E` 估计的是这个数，反解得到

```text
E* = −2^{32} ln(1 − E/2^{32})
```

`m = 16`、每个寄存器都是 24 时，`E = 0.673 × 16 × 2^{24} = 180657061.888`，修正值是 `184566526.762`。它大于 `E`，因为碰撞使真实基数大于不同哈希值的个数。

这个反函数只在 `E < 2^{32}` 时有有限值。`E` 从下方趋向 `2^{32}` 时基数趋向 `+∞`。`b = 4` 时余数有 28 位，`ρ(0^{28}) = 29`。16 个桶各看到一次余数为 0 的哈希后，每个寄存器都是 29，原始估计是 `0.673 × 16 × 2^{29} = 5781025980.416 > 2^{32}`。代码返回 `+∞`，也就是该公式的极限，而不是一个另外发明的有限修正。

### 为什么三个 if 不是依次覆盖

Figure 3 在版面上是三个独立的 `if`。若按书写顺序落下执行，第二个 `if` 在 `E ≤ 2^{32}/30` 时把 `E*` 设回原始 `E`。小范围的 `E` 总满足这个不等式，线性计数会被盖掉，`n = 0` 又变回大约 `0.7m`。这和 Section 4 (ii) 相反：正文说修正已经写进 Figure 3，并且就是为了去掉这个偏差。Figure 4 的说明也写明模拟包含 low cardinality correction。因此三个分支按互斥区间实现：小、中、大。`VERIFICATION_LOG.md` 第 1 轮记录了落下执行时测试看到的结果。

### log 的底

全文的 `log` 是自然对数。两处可以直接核对：

- 空桶模型写成 `m e^{−μ}`，所以 `μ = log(m/V)` 是 `ln`。
- Theorem 1 写 `β_∞ = √(3 log 2 − 1) ≈ 1.03896`。`√(3 ln 2 − 1) = 1.03896176…`，与这个数一致；若 `log` 是 `log2`，数值对不上。

`math.log` 就是这个对数。用 `log2` 会把大范围结果乘上 `1/ln 2 ≈ 1.442695`。第 2 轮的失败输出就是这个倍数。

## 标准误

Theorem 1：

```text
β_16 ≈ 1.106,  β_32 ≈ 1.070,  β_64 ≈ 1.054,  β_128 ≈ 1.046
β_∞ = √(3 ln 2 − 1) ≈ 1.03896
```

论文用的是 `≈`（PDF 里的 `.=`），只给到三位小数。Section 3.2 的积分在本目录的求积下约为 `1.10621`、`1.07083`、`1.05449`、`1.04663`。`β_32` 的第四位不是 0；测试用 `0.001` 的容差去对三位小数的印刷值，而不是假装印刷值等于积分的四位小数。

Figure 3 和摘要把实用标准误写成 `1.04/√m`。误差测试比较的是这个数，不是把 `β_m` 再嵌进估计器。

Section 4 根据中心极限定理说，估计大约有 65%、95%、99% 落在 1σ、2σ、3σ 以内。`test_intermediate_bias_and_standard_error` 用 `m = 256`、`n = 20000`、200 个均匀 32 位多重集检查偏差和这个覆盖比例。`n = 20000` 远小于 `2^{32}`，哈希碰撞的期望约 `0.05` 个，相对 `6.5%` 的标准误可以忽略，因此这批 32 位字就是 Figure 3 所说的模型。

## 合并

脚注 4：把文件分成若干部分后，收集各部分的寄存器，逐分量取最大。`merge` 生成新的草图，不改输入。观测本身是最大值，所以两部分即使重叠，分量最大值仍然等于把拼接流再扫一遍。测试同时覆盖了不重叠和重叠。
